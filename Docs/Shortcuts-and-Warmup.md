# Shortcut capture and startup warming

GlobalShortcut owns Windows registration and physical input hooks behind IGlobalShortcut. ShortcutChord stores modifiers, physical key codes and mouse buttons; JSON is only its persistence format. The native default uses CsWin32's VK_OEM_102 with Windows, preserving Win + <. MainProject does not declare a duplicate Windows virtual-key constant.

An ordinary one-key chord uses RegisterHotKey with MOD_NOREPEAT. Mouse chords and combinations with several ordinary keys use keyboard/mouse event hooks and a held-input set. There is no polling loop. Only the transition into a complete chord toggles the window; a held chord does not repeatedly toggle it. Mouse 4 and Mouse 5 use Windows XBUTTON1/XBUTTON2 messages. Injected keyboard input is passed through rather than being mistaken for a physical shortcut.

ShortcutRecorder consumes the native capture contract using the existing Core buttons. During recording, physical key/button events update the candidate. Releasing them preserves that candidate. A plain left click is reserved for the on-screen accept/cancel buttons, while Ctrl + left click and other modified left-click chords are assignable. Cancel restores normal registration without persisting the candidate. Failed registration restores the previous chord. Closing the recorder cancels an unfinished capture. Startup registration failure tries the native default and leaves tray access available if neither can register.

ModifierReleaseWaiter now awaits all Ctrl/Shift/Alt/Windows modifiers through key-release events before clipboard capture, rather than only waiting for Windows keys. This prevents a newly configurable shortcut's held modifiers from changing the generated Ctrl+C operation.

StartupWarmup is the one orchestration class for retained local engines. It initializes the existing translation and detector bridges, primes the current Bergamot/Töz directions, runs a silent Paradee sample without caching it as user speech, initializes both pronunciation pipelines including Misaki's neural fallback, then primes all available offline detectors. User commands cancel preparation immediately. Online attempts own fresh disposable engine contexts, so no disposable online session is artificially warmed or reused.

Controlled consumers exercised the actual native matcher for Ctrl + Mouse 4, Mouse 5, excluded bare left click, retained candidate, serialized round-trip and one activation per held chord. Actual C# Misaki resources produced phonemes, including distinct noun/verb pronunciations for “record.” Actual ONNX workers produced both pronunciation outputs; the FYLs demonstration sentence matched its published phoneme string. Browser-controller tests verified that both warm workers remain resident and that stale cancellation cannot complete or stop newer work. These are source-level and controlled runtime checks, not an HTTP test API.
