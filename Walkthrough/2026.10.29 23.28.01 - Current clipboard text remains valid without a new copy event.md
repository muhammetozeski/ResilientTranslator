# Current clipboard text remains valid without a new copy event

The user reported that text copied beforehand with Snipping Tool was ignored when the later Ctrl+C produced no clipboard change. Source inspection identified an early return on notification timeout and a second rejection based on unchanged clipboard sequence numbers. Capture did not clear the clipboard; it skipped reading already available text.

For 1.0.1, notification timeout and failed native copy proceed to the existing resilient clipboard reader. Sequence-number and HasText gates were removed; request object identity, serialized access and cancellation still control which result may reach the editor. Empty/nontext content starts no translation. The existing notification budget allows an actual new selection to arrive before reading.

The user requested a local trial before anything is uploaded to GitHub. Publication remains pending that trial. The source contract is documented in [window interaction](../Docs/Window-Interaction.md); native clipboard behavior must be confirmed by the user's manual trial rather than inferred from build completion.
