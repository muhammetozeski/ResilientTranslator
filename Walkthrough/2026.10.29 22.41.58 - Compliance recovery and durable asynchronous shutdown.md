# Compliance recovery and durable asynchronous shutdown

The user requested a full CSharpProgram/principle review while keeping release publication on hold and the supplied translation engine unchanged. Concrete issues included quadratic character-by-character string logging, unbounded memory diagnostics, unobserved cancellation callback completion, incomplete cleanup after a client-cancel error, invalid settings preventing startup, UI failures without an explicit recovery boundary and a blocking exit-time log wait.

The existing logger was retained and moved into Infrastructure. New shared persistence coordinates the existing serializer with atomic text replacement, backups and a durable pending snapshot. Locale resources use the same atomic writer and can recover malformed shipped files. UI recovery is explicit and does not gate native manual translation. On-demand font enumeration has primary/fallback providers and rejects late results after the picker closes.

The user clarified that process exit must follow the final persisted diagnostic. CompleteAsync now seals later accepted records and confirms a primary or emergency file flush to disk; failed destinations reject completion. Native exit awaits this asynchronously and remains open on failure. Controlled tests covered both success and failed sinks. Additional checks covered file locks, invalid values with preserved originals, duplicate locale keys, canceled callbacks, real installed-font enumeration, font failure/cancellation, renderer recovery and launcher argument fidelity from another working directory.

The generic control capabilities were ported to the source template independently of translator appearance. The active handwritten API descriptions were checked with a syntax-based inspection; native documentation normalization uses ordinary valid XML attribute whitespace. See [the compliance review](../Docs/CSharpProgram-Audit.md). Windows output was built, signed and installed locally. Publication and the user-requested post-release source build cleanup remain deferred.

The user then performed a real tray middle-click exit. Read-only inspection found zero installed application processes and the explicit final shutdown record as the last persisted entry.
