# Recovery after a single exhausted engine pass

Resilient Translator is a Windows MAUI Blazor application with a retained hidden window, bidirectional editable text, request-object ownership and one preloaded seven-language Lingua detector. The supplied engine remains unchanged. User commands supersede old work and the UI does not wait for network cleanup.

The application logs contained three failures for araba from Turkish to English around 14:53-14:55 on 2026-10-28. HTTP requests spent roughly 9.9 seconds in the connection queue and the application displayed failure after one exhausted engine pass. A later real-service call returned car; the historical transport condition was not reproduced. The missing application-level retry and alternate-path handling was established directly from source.

Recovery now owns fresh attempt sessions, bounded Polly retries, a sequential alternative, confirmed-only in-memory reuse and Unicode-safe large-input handling. Controlled tests verified recovery after transient errors, alternate execution after concurrent exhaustion, genuine final failure with original errors retained, cancellation and late-result rejection. Separate consumers verified that the original failure message is still shown after every strategy fails and that missing offline models can fall back to actual provider-side automatic detection. Technical details and verification boundaries are in [Translation recovery](../Docs/Translation-Recovery.md).
