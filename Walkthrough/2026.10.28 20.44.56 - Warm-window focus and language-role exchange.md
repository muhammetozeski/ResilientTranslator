# Warm-window input focus and language-role exchange

The translator retains the rendered hidden window and continues to use request-owned background translation recovery. This update makes each opening focus the first editable pane, hides the window when activation moves outside, and exchanges concrete language roles when a selector is changed to match the other pane.

Focus must follow the copy operation rather than steal the previous application's selection. Logical visibility must be cleared before native hiding, because hiding can itself emit a deactivation event. Existing Automatic restoration and destination fallback remain separate from the new user-selection collision rule. Both concrete exchange directions and the Automatic sequences passed controlled workspace tests. See [Window interaction](../Docs/Window-Interaction.md) for the corresponding source relationships.
