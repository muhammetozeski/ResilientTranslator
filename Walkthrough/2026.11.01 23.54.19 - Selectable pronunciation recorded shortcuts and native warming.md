# Selectable pronunciation, recorded shortcuts and native warming

The local signed 1.3.0 now contains both requested pronunciation pipelines, defaults to Misaki + neural and persists the choice in advanced settings. Native eSpeak and unrelated language data were removed. Keyboard/mouse chord recording uses existing Core controls and native registration/hooks, including Mouse 4/5; the default remains Win + <. Controlled consumers exercised actual pronunciation models, C# resources, cache ownership and the native chord matcher.

StartupWarmup owns retained-engine preparation and user-command cancellation. The first aggregate completion log did not establish that every independent step had succeeded: individual records exposed a MediaPipe failure. Its UMD loader was being evaluated with ES-module semantics, causing ModuleFactory and custom_dbg errors. A classic worker preserves the original loader semantics. The latest native run records successful warmup for translation, speech, both pronunciation pipelines and every detector, including MediaPipe; no sound was played.

Existing tests are separate consumer projects under the designated temporary workspace; no REST test API was found in application sources, DesignTests or earlier consumers. The user withdrew that investigation and requested completion. Do not claim a REST validation or a physical keyboard/mouse trial from the controlled matcher checks.
