# Native focus required before DOM editor focus

The user reported that both initial typing focus and outside dismissal failed in 0.3.0. The log showed successful DOM focus calls but did not establish native browser keyboard focus, and WinUI logical activation did not reliably report subsequent outside interaction. A completed DOM call must not be used as a substitute for observing the actual focused editor.

The focus path now activates and checks the real foreground window, focuses the native browser host, then focuses the input textarea. Native foreground notifications supplement logical activation; owned browser windows are filtered. Focus work belongs to the current presentation and is canceled when the window is dismissed. The concrete-language collision behavior from the preceding update is unchanged. See [Window interaction](../Docs/Window-Interaction.md).
