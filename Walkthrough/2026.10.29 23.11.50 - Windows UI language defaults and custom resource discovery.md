# Windows UI language defaults and custom resource discovery

The user resumed 1.0.0 publication and requested the seven XML resources inside the main package, followed by removal of local release archives and source build output. First-run UI selection now defaults to system; an unavailable Windows user UI culture resolves to English. Existing explicit selections remain preserved. The initial UI culture is captured before applying an application locale so returning to Automatic does not follow the previously selected app language.

The user also asked whether people could add their own language files. Resource loading already read UserData, but the settings picker and saved-selection validation were limited to the seven shipped cultures. The picker now discovers portable XML resources off the dispatcher; complete custom cultures can be selected and retained across process restart. Packaged defaults remain embedded and also ship as plain AppData/languages files. UserData remains the editable resource location.

Controlled consumers verified all seven culture selections, an unsupported Japanese culture falling back to English, and Automatic remaining stable after explicit locale changes. A Portuguese XML was discovered in actual SettingsPanel rendering, applied through the preference path, preserved on disk and restored after restart. An incomplete custom resource was rejected without changing the active English UI. See [preferences and layout](../Docs/Preferences-and-Layout.md).
